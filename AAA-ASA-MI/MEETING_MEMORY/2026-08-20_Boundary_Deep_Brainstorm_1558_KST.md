# 2. Boundary Core Question

Deep question:

> If relational configuration is considered before fixed substance/entity, what makes something 'inside' or 'outside' an INSTANCE?

Do not assume a priori that BOUNDARY is:

- a physical wall;
- a fixed Boolean membership field;
- intrinsic to the instance;
- singular;
- mutually exclusive;
- observer-independent;
- time-invariant;
- identical to ownership, authority, identity, memory, compute location, or legal status.

# 3. Candidate Boundary Hypotheses

These are brainstorming candidates, not adopted hypotheses.

## B-H01 — Boundary Non-Primitivity

BOUNDARY may not need to be defined before relations/configuration are known.

Possible direction:

RELATIONS / CONDITIONS -> CONFIGURATION -> BOUNDARY / INSTANCE

rather than:

FIXED ENTITY -> FIXED BOUNDARY -> RELATIONS

## B-H02 — Relational / Emergent Boundary

A boundary may emerge from the current configuration of relations rather than exist as an immutable property of an entity.

## B-H03 — Boundary / Instance Co-Constitution

INSTANCE and BOUNDARY may need to be solved/materialized together rather than one being strictly prior to the other.

Possible conceptual form:

(INSTANCE_t, BOUNDARY_t, RELATIONS_t) = Phi(context_t, history, environment, ...)

This is only a sketch; function, graph, fixed-point, event projection, or another representation may be superior.

## B-H04 — Typed / Multi-Boundary

One INSTANCE may have multiple simultaneous boundaries depending on relation type or purpose.

Examples of possible boundary dimensions:

- self / identity boundary
- memory boundary
- authority boundary
- information/disclosure boundary
- compute/runtime boundary
- legal boundary
- physical boundary
- organizational/community boundary
- causal/functional boundary

These boundaries need not coincide.

## B-H05 — Overlapping Boundary

A member/entity/process may simultaneously be internal under more than one INSTANCE or system view.

Therefore:

INSIDE(A) does not necessarily imply OUTSIDE(B).

## B-H06 — Perspective / Query Relative Boundary

A boundary may depend on the modeling question, observer, purpose, scale, or interaction being analyzed.

This raises the possibility that BOUNDARY is closer to a model/view/predicate than a globally absolute partition.

## B-H07 — Membrane / Interface Boundary

A useful boundary may be a selective interface controlling exchange rather than a hard separation.

Boundary semantics may therefore include:

- what may cross;
- under which conditions;
- in which direction;
- with what transformation;
- under whose authority;
- with what provenance.

## B-H08 — Boundary Change Produces Successor Instance

If boundary participates materially in instance constitution, a material boundary change may imply a new successor INSTANCE rather than mutation of one timeless identical instance.

This should be researched rather than assumed.

## B-H09 — Boundary Claim vs Observed Boundary vs Model-Inferred Boundary

Potential separation:

1. observed relational/functional integration;
2. system/model interpretation of that integration;
3. actor/node-declared or governed boundary status.

These may conflict and should not be silently collapsed.

## B-H10 — Unknown / Disputed Boundary Is Valid

A boundary may be UNKNOWN, PARTIAL, MULTIPLE, DISPUTED, or context-dependent without being treated as model failure.

This aligns with INIT's non-stalling currentization principle.

# 4. Boundary as a Possible 'View' over a Relational Substrate

High-value recall probe:

> Is an INSTANCE better understood not as a permanently stored container, but as a current materialized view/projection over a relational substrate under a boundary criterion?

Possible sketch:

RELATIONAL SUBSTRATE + TIME + ENVIRONMENT + QUERY / PURPOSE + BOUNDARY RULE

-> materialize

-> INSTANCE_t

This would fit the Owner's function-result intuition while remaining open to non-functional representations.

Potential implications:

- instance members could be evaluated/materialized rather than permanently intrinsic;
- different views may produce different instances over overlapping underlying material;
- succession could link successive materializations;
- boundary could be part of the selection/materialization mechanism;
- history may preserve which materialization rules were used.

This is a strong technical probe, not an adopted architecture.

# 5. Boundary as Modeling Compression / Coarse-Graining

Another research probe:

A boundary may be useful when treating a set/configuration of interactions as one INSTANCE gives better explanatory, predictive, computational, or operational compression than modeling every element separately.

Questions:

- Does a boundary identify a useful unit of explanation rather than a metaphysical essence?
- Does the useful boundary change with scale?
- Can one configuration support multiple valid boundaries for different tasks?
- Is 'objecthood' partially a coarse-graining decision?

Possible ancestor areas for later research:

- systems theory / coarse-graining
- information theory / compression
- causal emergence
- statistical physics / renormalization analogies

No claim is made yet that any of these is the correct implementation.

# 6. Boundary as Causal / Statistical Separation

Research probe:

Some mathematical/scientific abstractions define a useful boundary through conditional independence or causal separation rather than physical walls.

Possible ancestor concept candidates for later comparison:

- Markov blanket / probabilistic graphical models
- causal graph separation
- control/observability boundaries

Potential question:

> Can an INSTANCE boundary be defined by what screens internal variables from external variables under a given model, rather than by spatial inclusion?

This may be useful for some instance classes but should not be generalized prematurely.

# 7. Boundary as Operational Closure / Biological Membrane Analogy

Research probe:

Biological systems are not isolated; their boundaries selectively maintain organization while continuously exchanging matter, energy, and information.

Possible ancestor concept candidates:

- biological membrane
- autopoiesis / operational closure
- homeostasis
- cybernetics

Potential abstraction:

> A living boundary may be defined less by preventing exchange and more by regulating exchange while preserving/reproducing an organization.

This may be relevant to P0/liveness but must not be promoted into a universal rule without research.

# 8. Boundary and Mereology / Part-Whole

Deep problem:

'X is inside A' may mean many different things:

- X is a physical part of A;
- X is functionally constitutive of A;
- X is represented as a member of A;
- X is owned by A;
- X is authorized by A;
- X is remembered by A;
- X is recognized by A as self-related;
- X participates in A's relational configuration.

These are not equivalent.

Possible ancestor concept area:

- mereology / part-whole theory

INIT should avoid collapsing PART_OF, MEMBER_OF, OWNED_BY, AUTHORIZED_BY, RELATED_TO, REPRESENTS, and SELF_RECOGNIZED_AS into one boundary relation.

# 9. Boundary and Topology / Closure

Research probe:

Topology distinguishes interior, exterior, closure, and boundary relative to a space/topology.

Possible ASA-MI question:

> If the relevant 'space' is relational rather than geometric, could a boundary be derived from a closure rule over relations?

Example conceptual pattern only:

seed members + selected relations -> closure -> candidate instance -> boundary relative to closure

This may provide a formal way to avoid starting from fixed containers, but could also be over-mathematization. It should be adversarially compared to simpler representations.

# 10. Boundary and Category / Structural Views

Research probe:

Some mathematical/philosophical approaches characterize an entity substantially by how it relates/transforms with respect to others rather than by an exhaustive list of intrinsic properties.

Possible ancestor areas:

- category-theoretic morphism-oriented views
- structural realism
- process philosophy

These should be treated as abstraction legacy, not direct software requirements.

# 11. Boundary and Authority Must Be Separated

Important anti-collapse rule candidate:

`BOUNDARY / MEMBERSHIP != AUTHORITY`

Even if a Persona/process is modeled as internal to a Person-like instance under some self/memory relation, this does not automatically grant execution, delegation, financial, disclosure, or governance authority.

Likewise externality does not automatically imply zero authority; an external delegate may have scoped authority.

This reuses an existing broader AAA/PCS lesson but should be re-tested for ASA-MI's generic model.

# 12. Boundary and Succession

If instances are discrete and succession replaces metaphysical continuity, boundary evolution raises new questions:

- How much boundary change is compatible with a declared succession relation?
- Does materially different membership create a new successor? Probably yes at the instance level, but what does valid succession mean?
- Can boundary expansion or contraction fork a lineage?
- Can two successor instances inherit different overlapping subsets of predecessor relations/members?
- Is succession itself determined partly by relation/boundary transformation?

These should feed the RELATION research program.

# 14. INIT Minimal Boundary Representation — Anti-Stall Candidate

INIT probably should NOT require a final metaphysical definition of boundary.

A minimal implementation-compatible candidate should at least avoid forcing a single global inside/outside Boolean.

Possible minimal fields / semantics to research:

- boundary kind / dimension;
- subject or target;
- relation/membership assertion;
- time/context applicability;
- provenance / who or what produced the assertion;
- declared vs inferred vs observed;
- current judgment/confidence where needed;
- UNKNOWN / DISPUTED support;
- predecessor/successor refs when boundary materially changes.

This is only an anti-stall interface idea, not a frozen schema.
