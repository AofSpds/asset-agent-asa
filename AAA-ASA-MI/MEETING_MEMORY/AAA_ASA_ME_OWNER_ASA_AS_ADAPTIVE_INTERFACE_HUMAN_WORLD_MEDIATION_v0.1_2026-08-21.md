## Owner-explicit clarification

The Owner refined the metaphor for ASA from "shell" or generic "boundary" toward **interface (IF)**.

Candidate architecture:

DYNAMIC INTERACTION / PROCESS / MAPPING SUBSTRATE
    ↓
ASA = ADAPTIVE INTERFACE (IF)
    - translation
    - projection
    - abstraction
    - human-friendly stable views
    - provenance
    - explanation
    - uncertainty / invalidation conditions
    - reversible drill-down where possible
    ↓
HUMAN-FACING WORLD
    - Object view
    - Identity view
    - Relation view
    - Event view
    - API view
    - Narrative view
    - scoped constants/invariants

Key distinction:
ASA_AS_IF != METAPHYSICAL_BOUNDARY.

ASA should mediate interaction between humans and a dynamic interaction-first world substrate, without forcing the substrate itself to adopt human-friendly object permanence or fixed ontological boundaries.

Candidate principle:
HUMAN_FRIENDLY_STABILITY_WITHOUT_ONTOLOGICAL_REIFICATION.

This is a strong current Owner design/worldview hypothesis, not a selected canonical architecture and not Owner Acceptance.
