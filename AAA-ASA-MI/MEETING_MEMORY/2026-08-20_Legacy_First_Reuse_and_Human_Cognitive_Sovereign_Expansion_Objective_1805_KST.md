## 1. OWNER_STATED — Legacy-First / Reuse-Before-Invention

Owner's working method:

> If a mature existing theory / abstraction / component already exists, reuse it. Develop a new one only when adequate legacy cannot be found.

Owner analogy:

> If an off-the-shelf component already exists, there is no reason to 3D-print the same part ourselves.

Implications for ASA-MI:

- existing philosophy, mathematics, science, computer science, systems theory, cognitive science, ontology, process theory, etc. are candidate component libraries;
- ANCESTOR_CONCEPT research is not decoration; it is an explicit reuse search;
- novelty is not a goal;
- a new composition of existing components may still be useful, but novelty claims are unnecessary for project value;
- Codex/adversarial research should be instructed to search for stronger prior art before proposing a new abstraction;
- if an existing concept covers the need better, ASA-MI should adopt/adapt/reference it rather than reproduce it under a new name.

Working shorthand:

`LEGACY_FIRST / REUSE_BEFORE_INVENTION`

This is a research-method candidate, not yet a governed AAA Requirement.

Owner does not want the project to converge on a posture such as:

> "I have now achieved final enlightenment / final truth."

This aligns with ASA-MI P0 liveness/currentization direction:

- current interpretation may change;

## 6. Why This Matters to ASA-MI Specifically

ASA-MI is not merely a Persona-memory implementation exercise.

Its changing-Persona / memory / identity / relation / event / materialization research is one enabling research stream for the larger objective:

- external AI can participate more deeply in cognition;
- Persona can become richer and more persistent;
- cognitive boundaries may become more relational and extensible;

- and the system must remain revisable under P0 rather than declaring a final human ontology.

Therefore this objective should be considered during INIT task design without being silently converted into a technical Requirement.

## 7. Research Task Design Consequence

Future Codex / research task design should explicitly ask:

1. what mature existing theories/standards already cover each candidate abstraction;
2. what should be reused directly;
3. what needs adaptation;
4. what real gap remains after reuse;
5. only then, whether a genuinely new abstraction/implementation is required.

Default order candidate:

`LEGACY SEARCH → PRIOR-ART COMPARISON → REUSE/ADAPT → GAP IDENTIFICATION → NEW R&D ONLY IF NEEDED`

This order is research discipline, not novelty suppression. New combinations remain allowed where they produce better explanatory or implementation fit.
