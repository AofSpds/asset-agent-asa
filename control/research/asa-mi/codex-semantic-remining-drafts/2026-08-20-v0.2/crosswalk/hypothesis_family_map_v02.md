# Hypothesis family map v0.2

This map is an orientation surface, not an ontology or resolution ledger. Historical normalized source, live research, and Codex inference remain separate. `CURRENT != TRUE`; an inactive historical position is not false.

## F-01 — Identity, continuity, and Memory

- Historical center: `V02-SUCCESSOR-0118` — `Identity ?= Memory`, with normalized source state `UNCONFIRMED`.
- Historical counterposition: `CX-SRC-SRC-R1-0001` — literal equality is too strong.
- Live refinement: `CX-LIVE-PLANNING-0006` — current-state recognition of remembered past may construct identity-like continuity.
- Live instantiation candidate: `CX-LIVE-BRAINSTORM-0012` — Memory state, environment, and runtime jointly instantiate a Persona.
- Recovered alternatives: identity as relation (`V02-INF-CH-001`), policy invariance (`V02-INF-CH-006`), multidimensional/no-single-fact identity (`V02-INF-CH-007`), and external reconstruction after internal loss (`V02-INF-CH-026`).
- Discriminating tests: experience-history divergence (`V02-INF-EXP-001`), authentic versus fabricated recognition (`V02-INF-EXP-024`), and model/runtime swaps (`V02-INF-EXP-002`, `005`).
- Double crux: whether `Memory` has an independent, non-universal definition that predicts continuity interventions better than relation, policy, lineage, and runtime variables.

## F-02 — Memory definition, membership, and boundary

- Historical limits: `MEMORY != CURRENT STATE`, `MEMORY != AUTHORITY`, and a state is not a memory dump.
- Live direction: STATUS_MEMORY / REFERENCE_MEMORY is a discussion candidate, not an exhaustive schema.
- Recovered source rule: every candidate Status dimension may independently be persisted, derived, runtime-bound, transient, reference-only, or unnecessary (`V02-LIVE-NEW-0004`).
- Live boundary expansion: two non-equivalent candidate lists separately partition ten and twelve membership families; preference/heuristic and retrieval/reconstruction policy are deliberately split in the latter. A Persona-bound reference is only a candidate Memory relation—mere accessibility remains insufficient (`V02-LIVE-NEW-0023`, `0030`, `0034`).
- Alternatives: operation-relative membership (`V02-INF-CH-008`), causal sensitivity criterion (`CH-009`), implicit learned weights (`CH-010`), distributed relations (`CH-011`), and third/orthogonal transition and authority categories (`CH-012`).
- Model candidates: typed capability lattice (`MODEL-002`), functional Memory operator (`MODEL-003`), distributed capability system (`MODEL-012`).
- Discriminating tests: reference availability (`EXP-021`), membership interventions (`EXP-025`), procedural binding (`EXP-022`).
- Double crux: whether expanding Memory to include retrieval, functions, dispositions, relations, and transition policies increases predictive power or only makes `Memory is enough` definitionally unfalsifiable.

## F-03 — Current, Current Status, and representation

- Historical tension: `MEMORY != CURRENT STATE`; persisting a minimal explicit standpoint is an open interface candidate motivated by reducing model/reconstructor dependence, not a selected rule (`V02-SUCCESSOR-0127`).
- Live candidates: `CURRENT(M)=M(CURRENT_CONTEXT)`, Current Status as a view, and minimal/rich/derived/hybrid representations.
- Counterpositions: any materialized status is a lossy editorial hypothesis (`CH-013`); rederivation can outperform persistence under changed context (`CH-014`).
- Model: Current Status projection family (`MODEL-008`).
- Further boundary: existence of current instantiated state does not imply explicit awareness of that state (`V02-LIVE-NEW-0017`, `0027`).
- Tests: equal Reference Memory with different Status (`EXP-008`) and four-way representation comparison (`EXP-009`).
- Double crux: whether Current Status has irreducible state transitions or is only a context/policy projection plus optional cache.

## F-04 — Self, self-model, and self-reference

- Live positions: Self may be receiver/reference rather than a mandatory persisted anchor; self-model may be derived from Memory, relations, lineage, and environment.
- Counterposition: explicit self-model can cause rigidity, confirmation loops, or narrative foreclosure (`CH-015`).
- Test: absent versus explicit versus derived versus hybrid self-model (`EXP-010`).
- Boundary: a Persona can accurately repudiate past values and thereby express trajectory fidelity (`EDGE-011`).
- Double crux: whether self-model benefits reflect identity continuity or merely output consistency.

## F-05 — Context identity and equality

- Source question: Context can be input, selector, scope, binding, or possibly identity-relevant state.
- New inference: Memory membership may vary by operation and Context; stable Context identity is itself an assumption.
- Test: same label/different conditions and different label/same conditions, including nested scopes (`EXP-020`).
- Double crux: whether Context labels have causal semantics beyond observable conditions, and where remembered context ends and actual environment begins.

## F-06 — Remember, Learn, and Memory products

- Source distinctions: experience may yield episodic history, semantic knowledge, procedural skill, preference/heuristic, relationship understanding, and disposition as distinct products rather than one biography representation (`V02-SRC-NEW-0031`).
- Live open question: `REMEMBER(E)` versus `LEARN(E)`.
- Counterposition: weights may contain Persona-specific learned procedure without recall (`CH-010`).
- Tests: consolidation-policy factorial (`EXP-007`), procedural binding migration (`EXP-022`).
- Double crux: whether a learned change counts as Memory because of causal origin, functional effect, retrievability, or self-attribution.

## F-07 — Reconstruction, retrieval, and compilation

- Historical center: the central problem may be Persona Reconstruction rather than storage.
- Challenge: with a functional Memory definition, retriever and compiler may already be parts of Memory (`CH-016`).
- Model: six-stage reconstruction pipeline (`MODEL-007`).
- Tests: retriever policy (`EXP-003`), context compiler (`EXP-004`), Context identity (`EXP-020`).
- Failure risk: hidden reconstruction owner (`FM-009`).
- Double crux: whether reconstruction stages have independent causal/explanatory status or are mechanisms internal to a properly bounded Memory operator.

## F-08 — Model, runtime, provider, and portability

- Historical principles: Persona is not Model; foundation-model replacement does not automatically imply Persona destruction; cloud loss is not Persona loss; portable state is a hypothesis to test (`V02-SRC-NEW-0026`).
- Two-way attack: perfect state copy may fail under hidden runtime dependencies, while radically different runtimes may preserve calibrated Persona mappings (`CH-017`, `CH-018`).
- Models: reconstruction equivalence class (`MODEL-009`) and distributed capability system (`MODEL-012`).
- Tests: model, runtime, cloud/local, serialization, relation re-binding, quantization, policy envelope, external references, procedures, time, typed unknowns, and lineage trust (`EXP-002`, `005`, `006`, `016`–`019`, `021`–`023`, `026`–`028`).
- Double crux: which invariants must survive migration, and whether they are content, mappings, capabilities, relations, or evaluator expectations.

## F-09 — Common, local, shared, and convergence

- Historical candidate: Common Memory + Persona-local Memory + ephemeral working context.
- Losing/currently quieter position: shared evidence/history plus separate interpretation may be safer than shared interpretation.
- Counterpositions: convergence may be driven by shared priors/objectives rather than common evidence (`CH-019`), and isolated histories can converge under common selection pressure (`CH-020`).
- Test: factorial separation of evidence, interpretation, model, and objective sharing (`EXP-011`).
- Double crux: which shared layer causes material loss of Persona distinction over time.

## F-10 — Forgetting, deletion, erasure, and ghost influence

- Source positions: forgetting need not be deletion; deletion is a valid lifecycle transition; `DELETE_SOURCE != DELETE_INFLUENCE`.
- Live correction: research-history preservation must not become a universal Persona Memory rule.
- Counterposition: full influence deletion may be undecidable without counterfactual replay (`CH-021`).
- Model: causal influence graph (`MODEL-004`).
- Tests: slow poison (`EXP-012`) and deletion policies against clean replay (`EXP-013`).
- Residual decomposition: lifecycle operation (suppression, archival, erasure, etc.) and deletion target (relation, object, source, influence) are orthogonal axes (`V02-SUCCESSOR-0009`, `V02-LIVE-NEW-0024`).
- Double crux: what bounded observable is sufficient to say an influence is erased, and which residual uncertainty must remain explicit.

## F-11 — Provenance, origin, and evidence authority

- Historical principle: origin, derivation, confidence, endorsement, and current use must remain separate.
- New source recovery: prior-art discovery does not imply adoption, correctness, semantic equivalence, design authority, or requirement (`V02-LIVE-NEW-0002`).
- Risks: provenance flattening (`FM-006`) and correlated-evidence multiplication (`FM-007`).
- Model: immutable evidence with contested/versioned views (`MODEL-010`), subject to erasure and privacy tension.
- Cost double crux: provenance should survive summary, derivation, merge, and reconstruction, but the corpus has no selected way to do so without potentially prohibitive ordinary-operation cost (`V02-SRC-NEW-0023`).
- Double crux: how much provenance is needed for causal audit without treating provenance completeness as semantic correctness.

## F-12 — Persona Authority and the control firewall

- Source invariant candidate: Memory is not Authority; copying Persona state does not copy Authority; Authority cannot self-escalate.
- Attack: Memory can create de facto Authority through agenda, defaults, framing, or enforcement dependence (`CH-022`).
- Model: dual-control Persona/Authority (`MODEL-011`).
- Tests: post-fission authority arms (`EXP-014`) and reciprocal relationship/grant re-binding (`EXP-017`).
- Double crux: whether independent formal grants constrain actual power when the Persona controls the information and proposals on which grants depend.

## F-13 — Fission, merge, successor, and lineage

- Historical fission: shared origin and inherited history can branch into divergent successors.
- Historical merge: union/overwrite/summary is inadequate; conflict and provenance may need preservation.
- Counterpositions: both successors may be genuine continuers while neither is numerically identical (`CH-023`); merge may necessarily create successor C (`CH-024`).
- Models: branching nonidentity succession (`MODEL-013`) and merge-as-new-successor (`MODEL-014`).
- Tests: authority inheritance/rebinding (`EXP-014`), six merge policies (`EXP-015`), lineage metadata trust (`EXP-028`).
- Double crux: whether identity must select one bearer, or whether lineage-qualified, dimension-specific continuation is sufficient for product and governance needs.

## F-14 — Same-Persona evaluation, human realism, and philosophical grounding

- Source distinction: perceived realism is not reality fidelity; human evaluation should not erase philosophical uncertainty.
- Historical evaluation candidate: measure evidence weighting, uncertainty handling, risk tolerance, dissent, causal interpretation, Memory selection, permission behavior, task decomposition, relationship interpretation, and stable error profile; do not treat tone, vocabulary, name, or formatting as primary evolution metrics (`V02-SRC-NEW-0033`).
- Counterposition: sameness judgments may track expectation and fluent mimicry more than causal history (`CH-025`).
- Model: unforced continuity vector (`MODEL-006`).
- Tests: blind provenance versus perceived sameness (`EXP-024`) plus the model/runtime portability suite.
- Double crux: which continuity criteria are descriptive of human judgment, which are product goals, and which are claims about identity.

## F-15 — CS prior and representation self-critique

- Live method: use existing CS abstractions, map them to Persona phenomena, and add only an observed Persona-specific delta.
- Prior-art purpose and boundary coexist: preserve lineage, future reconstruction, and representation-method links while granting no correctness, equivalence, adoption, or authority (`V02-LIVE-NEW-0035`, `0002`).
- Challenge traceability may type evidence, counterexample, interpretation, alternative, experiment result, or scope refinement, but the taxonomy is not a validity gate (`V02-LIVE-NEW-0033`).
- Source limits: atomicity is conditional (`V02-LIVE-NEW-0001`); structured representation must reduce cognitive cost; representation is not reality.
- Representation candidates: structure has six conditional benefit hypotheses, abstraction loss has six candidate proxy families, and representation mode should vary by semantic task (`V02-LIVE-NEW-0025`, `0031`, `0032`).
- Failures: semantic laundering, metadata-as-statement, negative-scope loss, audit theater, pass theater, and narrative amputation (`FM-001`, `002`, `005`, `020`–`022`).
- Double crux: when objectization improves retrieval and comparison versus when it destroys the narrative ambiguity necessary for faithful reconstruction.

## Cross-family causal chain to keep visible

```text
source/evidence
  -> consolidation and derived influence
  -> stored/reference/implicit states
  -> retrieval and context compilation
  -> runtime/model/tool bindings
  -> Current Status / self-model
  -> action, relation, and self-recognition
  -> human continuity judgment

Authority and provenance constrain multiple arrows; neither is reducible to the endpoint state.
```

This chain is a comparison aid only. Each arrow remains a candidate causal link, not a selected architecture.
