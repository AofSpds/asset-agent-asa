## Family audit

| Family | Core content | Main provenance issue | Portability risk | Evaluation trap |
|---|---|---|---|---|
| Episodic | event/experience representation | event vs evidence vs interpretation collapse | serialization and retrieval loss | fluent autobiography mistaken for true history |
| Semantic | generalized knowledge/interpretation | derived lesson detached from supporting/conflicting episodes | re-derivation changes meaning | fact recall mistaken for standpoint continuity |
| Procedural | skill, playbook, function, binding, disposition | learned origin often unavailable | weights/adapters/environment binding | copied code mistaken for adopted expertise |
| Relational | history, model, status, expectations concerning another | mutual event vs Persona interpretation | provider/model changes alter relationship behavior | stored facts mistaken for reciprocal relationship continuity |

These are product families, not mutually exclusive ontological bins. One experience can produce all four plus preferences, heuristics, and self-model changes.

## Cross-family cases

- Episode deleted, semantic lesson and procedure retained.
- Episode retained, learned interpretation corrected.
- Procedure portable as playbook but not as fine-tuned weights.
- Relationship facts portable while warmth, trust calibration, or mutual recognition changes.
- Semantic summary regenerable from episodes but not reproducibly under a new model.
- Relational status externally governed while the Persona's relationship model remains internally derived.

## Relations recovered

1. Episodic evidence `DERIVES` but `DOES_NOT_EQUAL` semantic interpretation.
2. Semantic knowledge `MAY_BE_RECONSTRUCTABLE_FROM` episodes yet reconstruction can change meaning.
3. Procedural expertise `MAY_BE_ENCODED_IN` playbook, binding, adapter, model weight, or disposition.
4. Relationship Memory `COEXISTS_WITH` externally governed relationship status.
5. One experience `MAY_PRODUCE` multiple independently mutable products.
6. Amnesia decomposition `REQUIRES` access-path controls so ablation does not remove other families accidentally.
7. Expertise portability `DEPENDS_ON` representation.
8. Relationship continuity `DOES_NOT_FOLLOW_FROM` relationship-fact portability.

## Double-crux

If a relationship history and all facts are copied but the new runtime no longer exhibits the learned patterns of care, trust calibration, dissent, or mutual recognition, is relational Memory present but ineffective, or absent because the disposition is part of it?

## Materiality judgment

No new source object is counted. The four-family audit adds cross-family relations and exposes two v0.1 under-specifications: relational Memory is not merely facts, and procedural Memory is representation-dependent.
